# {{PROJECT_NAME}}

A `dudamel` project — a personal AI assistant that runs on your own
hardware, with a bundled `workouts` example app.

## Quickstart

This scaffold ships its `migrations/` directory empty (no revisions yet) so
the very first thing to do is generate one from the `workouts` app's models:

```
uv run dudamel db migrate -m init
uv run dudamel run
```

`dudamel run` applies any pending app migrations on startup, so once a
migration exists you don't need to run `db migrate` again unless you change
an app's models.

The dashboard comes up at `http://127.0.0.1:8787` (see `dudamel.toml`).
Log in with the token in `.env` (`DUDAMEL_WEB_TOKEN`) — rotate it any time
with `uv run dudamel token rotate`.

## Diagnosing problems

```
uv run dudamel doctor
```

Checks the database, migration state, each configured LLM tier, Telegram
and web token configuration, and Tailscale reachability, then prints every
registered tool with its safety flags (`read_only` / `confirm` / `origin`).

## Project layout

- `assistant.py` — registers your apps; `dudamel run`/`db migrate`/`doctor`
  all import it.
- `apps/workouts.py` — the bundled example app (tool + widget + job).
- `dudamel.toml` — LLM tiers, web/telegram/router configuration.
- `migrations/` — autogenerated app-schema migrations (`dudamel db migrate`).

See the `dudamel` package documentation for the full guide, including the
security model (confirm gates, the taint rule, budgets) and remote access
over Tailscale.
